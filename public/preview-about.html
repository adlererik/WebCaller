WebCaller security

This installation uses the experimental libsignal browser integration. The server operator has approved replacing the earlier Olm transport. The website address, phone identity and configured call-alert services are retained.

Engine: official libsignal 0.105.1 Rust core, pinned at commit 1738ead8a12ffe539f6309958123dadb16dc3b95, through a small experimental WebAssembly/storage adapter. The official protocol source is unchanged. This is not an official Signal browser client.

New messages, attachment-key manifests and call signaling use Signal session encryption established with PQXDH. The current library also exchanges SPQR/Triple Ratchet data. Application envelopes and prekey publications use Ed25519 signatures. New accounts have Ed25519 signing identities. Existing P-256 accounts keep their original P-256 identity pins and authorize a nonextractable Ed25519 signing key with a P-256 certificate; their identities, sessions and history are preserved. Historical P-256 signatures remain readable. Refresh both phones after this update; keep their browser site data. Files remain AES-256-GCM. Live audio/video remains WebRTC DTLS-SRTP: this experiment does not make live call media post-quantum secure.

The optional four security words still bind the accepted call media and authenticated application identities. Their existing Vodozemac SAS primitive is retained separately; message encryption no longer uses Olm. Read all four words to each other. Skipping the check does not stop a call.

Contact IDs, invitations, calling codes, timers, messages, media, alerts and call adaptation keep their normal workflow. Old Olm ratchets and incompatible test messages are not imported. Existing application identities and alert subscriptions are retained; new Signal session state uses a separate browser database. The earlier browser databases are kept for operator rollback.

After the upgrade

  1. Reload your usual phone page or reopen its existing Home Screen icon. Keep browser site data and the existing ntfy subscription.
  2. Have your contacts refresh too. Older loaded Olm pages cannot exchange encrypted traffic with this build.
  3. Send a message and make a call in both directions. Compare all four security words.
  4. Check locked-phone alert sounds on each device; browser and OS restrictions still apply.

Tests establish interoperability and reliability, not a proof of security. This new browser adapter has not had an independent audit. The website still supplies executable JavaScript, and an owned phone can expose plaintext. Large PQ key/session records and the extra module may increase startup and storage work; physical-phone performance is part of this trial.

Includes MIT WebCaller code, Apache-2.0 Vodozemac SAS and AGPLv3-only libsignal. Download the corresponding source (no private configuration or conversation data).
